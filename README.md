# AppDash Alpha

Windows PC의 로컬 서비스·에이전트와 자동화 스크립트를 등록하고 실행·종료·연결·이력을 관리하는 개인 워크스페이스입니다. UI 브랜드는 AppDash입니다. Node.js 24 이상과 SQLite를 사용하며 별도 npm 패키지 설치가 필요 없습니다.

## 시작·종료

- `AppDash.bat`: Node.js 24 이상을 확인하고 서버를 백그라운드로 시작한 뒤 브라우저를 엽니다. Node가 없으면 공식 배포본의 SHA-256을 확인해 로컬 런타임을 준비합니다.
- `Stop-AppDash.bat`: 이 설치의 서버와 AppDash가 소유한 앱 프로세스를 종료합니다.
- 기본 주소: http://127.0.0.1:4175
- `npm start`: CLI 실행. `npm test`: 임시 저장소·포트에서 검증.
- `APPDASH_PORT`: 1~65535의 다른 포트. `APPDASH_DATA_DIR`: 개인 데이터 위치.

창이나 탭을 닫는 것과 서버 종료는 다릅니다. 같은 설치는 재사용하고, 포트가 같은 다른 설치나 프로그램을 임의로 종료하지 않습니다.

## 두 가지 앱 유형

| 유형 | 카드 클릭 | 실행·예약 |
| --- | --- | --- |
| 서비스·에이전트 (`service`) | 꺼져 있으면 시작하고 준비 확인 후 실제 앱 UI를 새 탭으로 열기 | AppDash는 시작·종료와 상태·로그를 관리. 업무 예약은 해당 서비스 안에서 관리 |
| 자동화 스크립트 (`automation`) | 실행·예약 팝업 열기 | 입력 확인 후 지금 실행, AppDash 예약 관리. 상태와 로그·결과를 기록 |

화면 접속 URL의 유무로 구분합니다. `scheduled`는 신규 유형이 아닙니다. 예약은 자동화 스크립트의 실행 방식입니다. 옛 scheduled 설정은 읽을 수 있으며 URL이 없으면 automation, 있으면 service로 변환합니다. 옛 uiStart/uiStop 설정은 서비스의 start/stop으로 정리하고 이전 설정은 이력으로 보존합니다. 기존 서비스 예약은 AppDash에서 실행하지 않고 비활성 상태로 보존합니다.

서비스 카드 하단에는 시작·종료 / 더 보기, 스크립트 카드에는 예약 관리 / 더 보기를 둡니다. 스크립트 실행 중에는 중지할 수 있습니다. 유형·그룹은 카드 본문의 상태·예약 정보 아래에 표시합니다. 더 보기에서는 앱 관리·실행 기록·보관을 제공합니다. 외부에서 시작한 서비스는 외부 실행으로 표시하고 임의로 종료하지 않습니다.

실행 중 유형 변경은 먼저 종료해야 합니다. 실행 중 연결 설정을 바꿨다면 재시작 필요를 표시하고 현재 프로세스의 실제 URL을 유지합니다.

## 앱 등록과 제작

앱 만들기 · 연결하기에서 `appdash-gateway-config.json`을 가져와 검토하고 직접 등록합니다. 가져오기와 설정 점검은 프로세스를 실행하지 않습니다. 외부 코딩 AI에는 `skills/appdash-create-app/SKILL.md`를 전달하세요. AppDash가 내부에서 앱 코드를 생성하거나 범용 AI 에이전트·MCP 제어 서버로 동작하지는 않습니다.

Gateway는 공통 process 실행기이고 JSON은 앱별 선언적 설정입니다. executable과 args 배열을 분리하고 workingDirectory에는 실제 절대 경로를 씁니다. 기본 작업 제한은 300초, 서비스 준비 대기는 20초입니다. 서비스는 openUrl을 제공하고 start로 화면 서버를 시작합니다. 자동화 스크립트는 openUrl을 비우고 유한 작업을 start로 실행합니다.

앱에는 APPDASH_APP_ID, APPDASH_RUN_ID, APPDASH_INPUT_JSON, APPDASH_OUTPUT_DIR, APPDASH_CONNECTIONS_JSON, APPDASH_URL, APPDASH_TOKEN_ACCESS_KEY를 전달합니다. 서비스 내부 예약은 AppDash의 예약 API를 호출하지 않고 해당 앱이 자체 관리합니다.

## 자동화 스크립트 예약과 결과

예약은 Asia/Seoul의 매일·평일·매주, 여러 시각, 개별 활성·중단을 지원합니다. AppDash와 PC가 실행 중이어야 합니다. 동시 실행은 앱별 1개이고 같은 예정 시각은 영속 식별로 중복 처리하지 않습니다. 누락은 기본 건너뛰기이며 선택적으로 최근 8일의 각 예약별 마지막 1회를 실행합니다. 서비스의 예약은 AppDash에서 만들거나 실행하지 않습니다.

지금 실행은 AppDash 화면을 유지합니다. 입력이 필요한 앱은 입력을 받고, 기록 보기로만 로그 상세에 이동합니다. 결과 보관 기본값은 30일이며 결과 파일 정리는 이력을 삭제하지 않습니다. 로그는 최근 128 KiB, 알림은 최근 300개입니다. 실행 기록은 전체 이력의 필터·페이지 이동을 지원하고 로그는 자동 스크롤하지 않습니다.

## 연결·토큰·보안

연결 관리에서 HTTP API와 발신 웹훅, 중앙 토큰을 관리합니다. 연결 중단은 정보를 보존하고 새 실행을 차단합니다. 웹훅 검사는 실제 발송하지 않으며 별도 상태 확인 URL이 없으면 설정만 확인합니다.

토큰은 Windows DPAPI CurrentUser로 암호화하고 일반 API·목록에서 원문을 돌려주지 않습니다. 앱에 명시적으로 허용한 토큰만 주입합니다. `sdk/appdash-sdk.mjs`의 getToken은 환경변수를 우선 사용하고 fresh 조회는 실행 전용 권한과 현재 권한 범위를 확인합니다. 삭제·만료·회수는 새 전달과 조회를 막지만 이미 실행 중인 환경변수를 지우지는 못합니다. 지원하지 않는 OS에서 평문 저장으로 대체하지 않습니다.

서버는 127.0.0.1에만 바인딩하고 Host·Origin·변경 요청의 세션 토큰을 검증합니다. 결과 경로 이탈·링크를 통한 다운로드·정리를 막습니다. AppDash는 같은 OS 계정의 악성 앱을 격리하는 샌드박스가 아닙니다.

## 데이터·배포

개인 앱·설정·예약·실행·알림·암호화 토큰은 `.runtime/appdash.sqlite`의 records에 저장합니다. 예약 중복 식별은 occurrences에 저장합니다. 원본 연결 JSON은 가져오기용이며 등록 후 변경은 DB에 반영됩니다. 실행 결과는 `.runtime/results/<run-id>`입니다.

서버와 작업을 종료한 뒤 데이터 폴더 전체를 백업하세요. 실행 중 DB 파일만 복사하지 마세요. DPAPI 암호문은 다른 PC·Windows 계정에서 복호화된다고 보장하지 않습니다. `.runtime`, `.env*`, DB·로그·개인 결과는 Git에서 제외합니다.

새 clone은 앱·연결·토큰 0개로 시작합니다. DUMMY APP 예제 소스는 포함하지만 자동 등록하거나 특별한 미리보기 모드를 만들지 않습니다. 등록된 예제는 일반 앱처럼 관리·보관합니다. MotD는 별도 프로젝트의 서비스 예제이며 플랫폼 초기 데이터가 아닙니다.

실제 검증 범위와 미검증 항목은 VERIFICATION.md, 재구현 지시문은 AppDash-Alpha-Implementation-Prompt.md를 확인하세요. 인터넷 공개 SaaS·팀 계정·OAuth 자동 로그인·클라우드 실행·웹훅 수신 트리거는 현재 범위가 아닙니다.
