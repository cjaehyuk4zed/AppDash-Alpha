# AppDash

## 화면 개선과 DUMMY APP

홈의 큰 소개 배너를 제거하고 홈과 앱 사이에 대시보드를 추가했습니다. 대시보드는 실행 차단 앱, 최근 실행 문제, 만료 임박 토큰과 최근 연결 검사 문제를 보여줍니다. 앱 목록에는 이름순·최근 사용순, 즐겨찾기 필터, 필터 초기화가 있습니다. 신규 등록 폼은 기본·고급 설정을 구분하며 ‘설정 점검’은 경로·실행 파일·연결 참조만 확인하고 명령을 실행하지 않습니다.

DUMMY APP은 이 설치에서 사용자가 요청해 일반 앱으로 등록한 샘플입니다. 별도 미리보기 모드나 전용 UI는 없으며 다른 앱과 동일하게 수정·실행·예약·보관합니다. 실행하면 examples/dummy-app/main.mjs가 로컬 보고서와 요약 JSON을 생성합니다. 새 clone에서는 자동 등록하지 않습니다. 샘플 코드를 사용하려면 실제 폴더 경로로 앱을 직접 등록하세요.

실행 중 상태는 최근 기록 500개 제한과 별도로 조회합니다. 실행 기록에서 서비스 상세를 열면 로그와 종료 버튼이 유지되고, 앱 카드로 시작한 경우에만 서비스 URL로 이동합니다. 작업·준비 확인 시간 초과는 실패 알림을 남깁니다. 동시 실행 때문에 예약이 차단되면 사유를 기록합니다. 연결 일시 중단은 새 실행을 막으며 기존 실행에 이미 허용된 토큰의 최신 조회는 유지합니다. 토큰 삭제·만료·앱 권한 제거는 최신 조회를 차단합니다.

서비스 연결은 마지막 검사 시각·결과와 사용 앱을 표시합니다. ‘설정 확인’ 및 ‘HTTP 응답 확인’은 외부 서비스 인증 성공 검증과 구분됩니다. 알림함은 개별 읽음과 안 읽은 알림 필터를 제공하며, 후속 실행 정상 여부는 읽음과 별도로 표시합니다. 설정에서 실제 결과 용량, 7일 내 정리 예정 용량과 백업 절차를 확인할 수 있습니다.

Windows 우선 개인용 로컬 앱·서비스 대시보드. Node.js 24+, SQLite, 한국어 브라우저 UI를 사용하며 외부 패키지가 필요 없습니다. 새 설치에는 등록 앱·연결·토큰이 없습니다.

## 시작과 종료

`AppDash.bat` 더블클릭 → 실행 환경 준비 → `http://127.0.0.1:4175` 열기. 서버·시작·종료 스크립트의 기본 포트는 모두 4175입니다. 설치된 Node.js 24 이상을 재사용하며, 없으면 공식 nodejs.org의 최신 24.x Windows ZIP을 다운로드해 공식 SHA-256과 비교한 뒤 `.runtime`에 풉니다. 관리자 권한이나 전역 설치 변경은 필요 없습니다. 실행 정책 Bypass는 해당 PowerShell 프로세스에만 적용됩니다.

`Stop-AppDash.bat`는 준비 API에서 설치 경로를 확인하고 같은 설치에만 종료 요청을 보냅니다. AppDash 설정 화면에서도 종료할 수 있습니다. 브라우저 탭을 닫아도 서버와 서비스는 계속 실행됩니다. 다시 실행하면 기존 서버를 사용합니다. 다른 설치 또는 프로그램이 포트를 점유하면 종료하지 않고 오류를 표시합니다. 오류 로그: `.runtime/server-error.log`, 표준 출력: `.runtime/server.log`.

CLI: `npm start` (또는 `node server/main.mjs`), Ctrl+C로 종료. 별도 설치 명령은 없습니다. `APPDASH_PORT`, `APPDASH_DATA_DIR`로 포트와 데이터 위치를 바꿀 수 있습니다. 같은 데이터 위치의 서버를 서로 다른 포트에서 동시에 실행하지 마세요. Windows만 제품 지원·검증 대상입니다. 타 OS에서는 중앙 토큰 저장이 명시적으로 거부되며 앱 자체 인증을 사용할 수 있습니다. 포터블 Node 최초 준비에는 인터넷이 필요합니다.

## 앱 관리·예약·실행 기록

앱 관리는 개요 / 실행 설정 / 연결·토큰 / 예약 탭으로 나뉩니다. 탭 이동은 입력을 유지하고 닫기·다른 화면 이동 시 저장되지 않은 변경을 확인합니다. 등록 설정 이력에서 변경 항목을 비교한 후 복원하며, 비교 이후 설정이 바뀌면 복원을 거부하고 다시 비교하도록 안내합니다. 앱 소스·외부 데이터·예약 시간표는 복원하지 않습니다.

예약 관리에서 매일·평일은 요일 선택을 생략하고 매주는 요일을 지정합니다. 편집 중 요약 문장과 다음 실행 시각을 갱신하고 비활성 예약은 중단됨으로 표시합니다. 저장 전 취소한 내용은 적용되지 않습니다.

실행 기록은 앱·상태·기간·직접/예약 필터, 소요 시간, 이전/다음 페이지를 제공합니다. 실행 상세에서 로그를 검색·복사·다운로드할 수 있으며 수동 스크롤 위치를 유지합니다. 자동 스크롤 기능은 없습니다. 결과 만료일은 현재 앱 보관 기간 기준으로 표시합니다. 재실행은 확인 화면에서 입력을 검토한 뒤 현재 앱 설정으로 수행합니다. 신규 실행은 원래 실행 입력을 보관하며, 입력이 저장되지 않은 기존 기록은 현재 앱 기본 입력을 사용한다고 안내합니다.

## 앱 등록

앱 만들기 · 연결하기에서 두 가지 안내를 펼칠 수 있습니다. 외부 AI에 `skills/appdash-create-app/SKILL.md`와 요구사항을 전달하거나, `templates/appdash-gateway-config.json`을 직접 수정합니다. 앱 소스를 PC에 준비하고 JSON을 가져온 뒤 이름, 절대 작업 경로, 실행 파일과 인수 배열을 검토·등록합니다. 가져오기와 등록만으로 실행되지 않습니다. 셸 연산자는 자동 해석하지 않으며 필요한 경우 셸 호스트를 명시하세요.

카드로 실행하면 새 탭에 진행 화면이 열립니다. 지속 서비스는 준비 확인 후 앱 URL로 이동하고 기존 실행을 재사용합니다. 카드의 수정 버튼은 실행하지 않습니다. 예약 앱은 지금 실행과 예약 관리를 먼저 제공합니다. 앱 관리에서 입력, 즐겨찾기, 연결·토큰, 보관, 설정 이력 복원을 관리합니다. 보관은 새 실행과 예약을 중단합니다. 실행 중 프로세스는 실행 기록에서 별도로 종료할 수 있습니다. 보관 해제·설정 복원은 중단된 예약을 몰래 재활성화하지 않습니다. 설정 복원은 앱 소스와 외부 데이터를 되돌리지 않습니다.

## 예약과 실행

Asia/Seoul 기준 매일·평일·매주 복수 예약. 편집 후 저장해야 반영되며 취소는 원래 예약을 유지합니다. 기본 동시 실행 수는 앱당 1개. 예정 시각별 처리 ID를 SQLite에 먼저 기록하므로 자동 재시도로 외부 부작용을 반복하지 않습니다. 기본 누락 정책은 건너뛰기이며 선택적으로 최근 8일 내 각 예약의 마지막 누락 1회를 실행합니다. PC와 AppDash가 실행 중일 때만 동작하며 부팅 자동 실행은 설정하지 않습니다. 프로세스 이름 전체를 종료하지 않고 현재 실행기가 소유한 프로세스 트리만 종료합니다. 서버 재시작 시 이전 실행은 중단됨으로 기록하고 PID로 재소유하지 않습니다. 비정상 종료 후 남은 앱은 사용자가 확인해야 합니다.

## 연결과 토큰

서비스 연결은 HTTP API 또는 발신 웹훅 대상입니다. 로컬 실행기는 별도 연결이 아닙니다. 일시 중단은 정보를 보존하고 새 실행을 차단합니다. 해지·중단 전에 영향 앱과 활성 예약 수를 보여줍니다. 검사 시 상태 확인 URL이 있으면 GET만 수행하고, 없으면 주소·인증 참조만 확인합니다. 웹훅 대상에 테스트 전송하지 않습니다. 인증 환경변수 참조는 앱에서 사용할 이름으로 전달되는 기존 서버 환경변수입니다. 상태 검사는 인증 헤더를 자동 구성하지 않는 기본 HTTP 도달성 검사입니다.

중앙 토큰은 Windows DPAPI CurrentUser로 암호화합니다. 복호화 키를 DB 옆에 저장하지 않습니다. 같은 Windows 계정·PC의 DPAPI 환경이 필요하며 암호문만 옮겨 쓸 수 있다고 보장하지 않습니다. 일반 관리 API는 원문을 반환하지 않습니다. 지정한 토큰과 사용 연결의 토큰만 앱에 주입합니다. 시스템·AppDash 변수 이름과 중복 토큰 변수는 금지합니다. 앱 자체 `.env` 사용도 가능합니다.

`sdk/appdash-sdk.mjs`의 `getToken(name)`은 환경변수 우선, `{fresh:true}`는 실행 전용 API를 사용합니다. 권한은 실행 중인 앱의 현재 설정과 허용 토큰에 한정되고 종료 시 만료됩니다. 토큰 교체·삭제·만료는 새 전달·조회에 적용되며 이미 주입된 환경변수는 회수하지 못합니다. 로그는 줄 단위로 모아 토큰과 실행 권한을 마스킹합니다. 64 KiB보다 긴 개행 없는 출력 줄은 생략합니다. 앱이 토큰을 인코딩·변형해 출력하거나 자체 파일에 저장하는 것은 방지할 수 없습니다.

## 저장·백업·제한

개인 데이터는 Git 제외 `.runtime/`(또는 지정 디렉터리)에 저장됩니다. 서버를 종료한 뒤 전체 데이터 폴더를 백업하세요. SQLite에는 앱, 설정 이력, 예약, 실행 기록, 알림, 암호화 토큰이 있습니다. 시작 시 기존 데이터를 유지하며 스키마 버전은 1입니다. 배포용 소스에 사용자 앱은 포함되지 않습니다.

결과는 실행별 `results/<run-id>/`에 저장되며 새 앱 기본 보관 기간은 30일입니다. 시작 시와 매시간 만료 결과만 정리하며 실행 이력은 삭제하지 않습니다. 로그는 실행별 최근 128 KiB, 알림은 최근 300개를 유지합니다. 홈 요약은 최근 500개 실행을 사용하며 실행 기록 화면에서는 앱·상태·Seoul 기준 기간·실행 구분 필터와 페이지 이동으로 전체 이력을 조회합니다. 페이지당 표시 수는 설정을 따릅니다. 결과 목록은 최대 1,000개입니다. 결과 다운로드는 등록 실행의 일반 파일만 허용하며 symlink와 경로 이탈을 거부합니다. 일반 파일 다운로드도 앱이 쓰는 동안 변경될 수 있습니다.

루프백 바인딩, Host/Origin 검증, 변경 요청의 관리 세션 검증을 적용합니다. 같은 OS 계정의 악성 앱을 격리하는 샌드박스가 아니며 관리자 명령·불신 앱을 안전하게 만든다고 주장하지 않습니다. 브라우저 UI에 비밀 입력을 넣으면 마지막 입력 저장에 포함될 수 있으므로 인증정보는 토큰 관리 또는 앱 자체 인증을 사용하세요. OAuth·자동 토큰 갱신·원격 실행·수신 웹훅·내장 AI 개발은 구현 범위가 아닙니다.

## 검증

`npm test` — 임시 저장소·별도 포트에서 실제 HTTP API, 로컬 프로세스, SQLite, 예약 계산, 결과·권한·DPAPI 경로를 검사합니다. 제품 `.runtime`에 테스트 앱을 넣지 않습니다. Windows에서 실행해야 Windows 전용 프로세스 트리와 DPAPI 검사가 포함됩니다. 실제 검증 결과와 미검증 범위는 작업 완료 보고를 확인하세요.
